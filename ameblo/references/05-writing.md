# 工程4：導入文

以下の執筆基準に従う。

冒頭3文以内でKWへの主要回答を示す。

必要に応じて結論が変わる条件や
代替手段も短く説明する。

一般論を長く続けない。

変動情報の最終確認日は、
実際に確認した日を導入文末尾へ原則1回だけ記載する。

記事作成日を確認日として代用しない。

## 冒頭配置

原則として以下の順とする。

1. 導入文
2. Ameba Pick挿入指示①
3. この記事を読んでわかること
4. 最初のH2

案件紹介が不自然な場合は
Ameba Pick挿入指示①を省略できる。

「この記事を読んでわかること」は
見出しタグを使わず、具体的結論5項目とする。

# 工程5：本文執筆

以下の執筆基準に従う。

工程3.5で確定した構成を使用する。

各H2直下に結論・概要を置く。

各H3では根拠、数値、条件、例外、比較などを具体化する。

文章は結論→理由→詳細を基本とする。

検索意図を満たす範囲で必要な情報を深掘りする。

## 独自切り口

採用済みの独自切り口は必ず本文に実装する。

単に「競合にない」と紹介するだけで終わらせない。

読者が何を判断できるようになるかを、
確認済みの数値・条件・比較・判断分岐等で説明する。

## 案件訴求

次の流れを基本とする。

検索意図
→ 読者の判断基準
→ 選択肢の比較
→ 指定案件の合理的な価値

案件が向かない条件や
他社を選んだ方がよい条件も必要に応じて示す。

## Ameba Pick

AIは実際の商品リンクを挿入しない。

商品ID・商品カード・広告URLを生成しない。

手作業用HTMLコメントだけを残す。

原則2箇所を候補とする。

挿入指示①：導入文直後

挿入指示②：原則2つ目のH2直前

ただし検索意図と情報順に応じて
挿入指示②を適切な位置へ移動できる。

紹介に合理性がない場合は無理に設置しない。

## HTML

references/02-ameblo-html.mdを正とする。

- アメブロ投稿用のシンプルなHTMLを使用
- 本文のh1は使用しない
- H2/H3を基本とする
- 通常段落はp
- 適切にul・ol・tableを使用
- スマホで読みやすい表と段落にする
- JavaScript・iframe等の禁止タグを使用しない
- WordPress/Gutenberg/SWELL用コードを使用しない
- SWELL吹き出しを使用しない
- 外部アフィリエイトコードを生成しない
- 未確認URLを使用しない
- 画像・SNSは必要なら手動挿入コメントを残す
- 作業に不要なコメントや空タグを残さない

## まとめ

最後にまとめH2を置く。

本文で説明済みの具体的結論8〜15項目を整理する。

新事実や重複で水増ししない。

## 執筆品質
読者タイプごとの結論、向く人・向かない人、総額や適用条件、代替案を必要に応じて説明する。
提供された本人の実体験と調査情報を区別する。未経験の商品を「使ってみた」と書かない。
引用は必要最小限にとどめ、引用箇所と確認済み出典を明確にする。競合の構成・文章の複製を避ける。
根拠なくNo.1・最安・最高額と断定しない。数値比較では比較対象・時点・条件を一致させる。
文字数を満たすために一般論、同義反復、不要FAQ、無関係な話題を追加しない。
