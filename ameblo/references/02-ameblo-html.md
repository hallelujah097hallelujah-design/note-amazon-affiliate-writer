# アメブロHTML・装飾基準
履歴の明示仕様から再構成した基準として使用する。実際の投稿画面での表示・許可タグは公開前に確認する。

## HTML全文
- 記事タイトルはHTML本文外へ出し、本文のh1は使用しない。
- 本文フラグメントとしてh2、h3、p、ul、ol、li、strong、a、必要なtableを基本にする。
- h2の直下に結論・概要を置き、その下にh3を配置する。見出し階層を飛ばさない。
- 通常段落はpを使い、短い段落でスマホの可読性を確保する。空タグや連続brによる余白調整をしない。
- 表は比較判断に必要な項目だけに絞る。列数が多い場合は分割し、thで項目を明確にする。
- 重要条件の強調にstrongを使い、過剰な装飾をしない。インライン装飾が必要なら最小限にする。
- WordPress/Gutenbergコメント、ショートコード、SWELL固有クラス、吹き出しは使わない。
- script、iframe、form、object、埋め込み実行コード、イベント属性、外部CSS読み込みは出力しない。
- 公式情報など通常リンクは実際に確認したURLだけを使う。URLを推測しない。
- 特殊文字は適切にHTMLエスケープし、タグの対応と入れ子を検査する。

## 冒頭とまとめ
順序は導入文、必要なAmeba Pick挿入コメント①、具体的結論5項目の「この記事を読んでわかること」、最初のh2とする。
「この記事を読んでわかること」には見出しタグを使わずpとリストを使う。
最後にまとめh2を置き、本文で説明済みの具体的結論8〜15項目を整理する。

## 手動挿入コメント
実際のPick商品リンク、商品ID、商品カード、広告URL、他社ASPコードを生成しない。
必要な位置に、紹介対象・適する読者・選定理由・確認すべき条件を具体化したコメントだけを残す。

```html
<!-- Ameba Pick手動挿入①：紹介対象＝商品名またはカテゴリ。対象読者＝本文に基づく条件。理由＝この位置で検討できる根拠。確認＝掲載可否・対象商品・価格・成果条件・広告表示。実際のカードは管理画面で選択する。 -->
```

候補①は導入文直後、候補②は原則2つ目のh2直前とする。ただし判断材料の後へ移動し、合理性がなければ省略する。
画像やSNSは必要なときだけ手動挿入コメントを残す。画像URLやSNS URLを捏造しない。
内部メモ・採点・調査DB・未解決のプレースホルダーを記事本文に混ぜない。必要な手動作業コメントだけを例外とする。
広告表示を一律に不要と判断しない。公式の現在仕様・広告主条件と実際の表示を確認し、必要な表示を満たす。
対応済みの作業コメントは公開前に削除する。
