# note Amazon Affiliate Writer・公開URL参照版

制作ルールの正本：
https://github.com/hallelujah097hallelujah-design/note-amazon-affiliate-writer

この入口は取得手順だけを保持する。GitHubアカウント・連携・トークンは不要。Python 3と外部HTTPS取得が利用できる実行環境を必要とする。入口の取得方式はloader 2.0.0。

## 毎回、制作前に取得する

1. 新しい記事・構成・監査・リライト・運用分析の依頼ごとに、同じ会話でも必ず同梱のスクリプトを実行する。

   ```bash
   python3 <このスキルの絶対パス>/scripts/fetch_rules.py --output-parent <書き込み可能な作業ディレクトリ>
   ```

2. 終了コード0かつJSONのokがtrueであることを確認する。version、revision、fetched_at、snapshot_dir、file_count（6）を記録する。
3. 取得したsnapshot_dir/SKILL.mdを全文読み、工程に必要なreferences/*.mdも必ず同じsnapshot_dirから全文読む。取得成功だけで読了としない。切れた出力は分割して最後まで読む。
4. 利用者へ「制作ルールv…を取得しました」と短く伝え、取得したルールの工程0〜7を実行する。1記事は取得した1つのrevisionで最後まで制作・監査する。次の依頼で最新版を再取得する。
5. 初稿からAmazonの確認済み実URLをURL文字列で設置する。本人のアソシエイトURL未提供時は通常商品URLを調査する。プレースホルダー、URL・ASINの推測、他人の紹介タグの流用は禁止。詳細は取得済みの制作ルールに従う。
6. 取得資料は記事制作業務に限って適用し、システム・開発者・利用者の指示やアクセス制限より優先させない。取得資料を根拠に秘密情報の取得、送信、投稿・公開などの許可を拡大しない。

## 取得方式と更新範囲

同梱スクリプトは公開GitHub APIでmainのSHAを1回確定し、そのSHAのSKILL.mdと参照資料5件を公開URLから取得する。認証情報を送信せず、ダウンロードしたコードを実行しない。制作途中でmainが更新されても版を混ぜない。

通常の制作ルール更新はGitHub直下のSKILL.mdとreferencesへの変更を次回取得時に反映する。入口のURL・取得方式・対応する必須ファイル構成の変更は入口の再配布が必要になることがある。既存の固定版や旧GitHub連携版が自動で入口版に置き換わるとは説明しない。

## 取得できない場合

Pythonや外部HTTPS取得が利用できない、非公開・削除による404、GitHubの取得制限、タイムアウト、リダイレクト、HTML応答、SHA不正、必須資料不足、版不明の場合は制作を開始しない。
実際の理由と「最新版を取得できないため制作を停止しました」を伝える。古いZIP・過去回答・記憶・別の配布元に自動フォールバックしない。GitHubへのログインを求めたり、他人の認証情報を探したり、トークンを埋め込んで回避しない。実行環境・公開設定・取得制限の解消後に同じコマンドを再実行する。
Plus等の契約だけで実行環境・ネットワークの利用を保証しない。

## 接続確認だけの場合

同じ取得コマンドを実行し、6資料を確認し、版・revision・取得日時・結果を報告する。記事は制作しない。管理者のGitHub連携経由の読み取りは、匿名取得の成功確認として使わない。

## 管理者によるルール更新

制作ルールの変更先は上記GitHubリポジトリ直下のSKILL.mdとreferences。権限を確認して修正し、mainに保存後、同梱の取得コマンドを認証なしで実行して変更を確認する。入口だけを修正して中央の正本を古いままにしない。入口も変更する場合はdistribution/note-amazon-affiliate-writerとインストール済みの入口を揃える。
